# Teaching design decisions

Teaching intent: make the consequences of delay, failure and concurrency observable through relevant decisions, concrete cases and manipulable figures.

This project now leads each chapter with one concrete case and one manipulable activity. A learner changes a relevant condition, predicts an outcome, sees state/feedback, and then reads the formal explanation. Original diagrams support the same concept rather than decorating a text-only lesson. A separate interactive classroom provides direct links to every scene.

Keep three evidence types distinct: browser teaching models, saved observations from real processes, and independently executable exercises. Never animate unrecorded packets or relabel fixture output as live telemetry. Preserve counterexamples: the stale read's verdict changes at the real-time boundary; a new retry ID defeats deduplication; a high-water-only fence can accept an old generation before seeing the new one. Do not count page/test totals as measured learning gains.

The course map links one verified university course to all seven units, with prerequisites and public-access boundaries. These runnable exercises remain independent originals, not university assignment solutions. Preserve the first-edition real baselines when extending the learning interface.
